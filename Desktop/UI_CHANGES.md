# UI界面变化说明

## 1. 扫描配置界面变化

### 新增内容
在扫描配置界面中，在扫描规则选择区域和开始扫描按钮之间，新增了：

```
上传设置
☐ 自动上传扫描报告到服务器
```

### 界面布局
```
扫描配置
├── 目标路径选择
├── 扫描规则信息
├── 上传设置 (新增)
│   └── ☐ 自动上传扫描报告到服务器
└── 开始扫描按钮
```

### 功能说明
- 复选框默认未勾选（对应配置文件中 `auto_upload_reports: false`）
- 勾选后，设置会立即保存到配置文件
- 下次启动应用时会保持之前的设置状态

## 2. 漏洞详情界面变化

### 原始界面问题
- 漏洞列表直接显示在界面中
- 当漏洞数量多时，界面会变得很长
- 没有滚动条，用户需要调整窗口大小才能查看所有内容
- 长代码片段会影响界面布局

### 改进后的界面
```
漏洞详情
├── 统计信息
│   ├── 总计发现 X 个漏洞
│   └── 严重: X  高危: X  中危: X  低危: X
├── 分隔线
└── 滚动区域 (新增)
    ├── 漏洞1: 标题 (严重性)
    │   ├── 文件: /path/to/file
    │   ├── 行号: 123
    │   ├── 代码片段: (带水平滚动条)
    │   └── 描述: 详细描述
    ├── 漏洞2: ...
    └── ...
```

### 滚动功能特性
1. **垂直滚动**：
   - 主列表区域支持垂直滚动
   - 最大高度为可用窗口高度减去20像素
   - 自动显示滚动条（当内容超出可视区域时）

2. **水平滚动**：
   - 每个漏洞的代码片段独立支持水平滚动
   - 代码显示区域最大高度150像素
   - 防止长代码行破坏整体布局

3. **界面优化**：
   - 添加漏洞统计信息
   - 改进视觉层次和间距
   - 保持响应式设计

## 3. 状态栏显示

### 上传状态显示
在底部状态栏中，当启用自动上传时会显示：
- 扫描完成后：`正在上传报告...`（带旋转图标）
- 上传成功：`报告上传成功，ID: xxx`
- 上传失败：`报告上传失败: 错误信息`

## 4. 配置文件变化

### 新增配置项
在 `config.json` 文件的 `server` 部分新增：
```json
{
  "server": {
    "base_url": "http://127.0.0.1:5000/api/v1",
    "auto_upload_reports": false,
    ...
  }
}
```

## 5. 用户体验改进

### 自动上传功能
- **便利性**：用户无需手动上传报告
- **一致性**：自动使用标准化的元数据
- **可控性**：用户可以随时启用/禁用此功能

### 滚动条功能
- **可用性**：大量漏洞时界面仍然易于导航
- **可读性**：代码片段不会影响整体布局
- **效率性**：用户可以快速浏览所有漏洞

## 6. 兼容性说明

### 向后兼容
- 现有配置文件会自动添加新字段（默认值为false）
- 不影响现有的手动上传功能
- 保持所有原有功能不变

### 升级路径
- 用户升级后首次运行时，自动上传功能默认关闭
- 用户可以根据需要手动启用
- 配置会在用户首次修改时自动保存
